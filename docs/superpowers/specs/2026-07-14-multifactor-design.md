# 中证500基准多因子模型——技术设计文档

## 1. 设计目标

采用配置驱动的模块化流水线实现需求文档。核心原则是时间隔离优先于模型复杂度、可审计优先于最高回测收益、研究多空与可交易回测边界清晰，并复用 `quant_platform` 的数据湖与回测能力而不改写其 5 因子日频 MVP。

## 2. 方案选择

### 2.1 已选方案：模块化研究流水线

将系统拆分为数据接入、时间点样本、因子处理、滚动训练、NNI 调参、模型选择、组合构建、研究回测、RQAlpha 验证和报告模块。模块之间只交换定义明确的表或产物清单。

### 2.2 未选方案

- 单体脚本：实现快，但难以隔离未来函数、复用缓存和定位差异。
- 完整研究平台：包含任务调度、实验数据库和 Web UI，首版成本高且超出基准模型目标。

## 5. 核心数据契约

### 5.1 月度因子面板

主键为 `(signal_date, instrument)`，至少包含：

- `trade_date`：实际执行或收益起算日；
- `universe_member`：历史时点是否属于中证500；
- `industry_code`、`float_market_cap`；
- 因子列；
- 可交易状态及剔除原因；
- 数据可用时间戳。

因子值分层固定为：`source_value`（供应商字段值）→ `recipe_value`（配方结果且不做方向翻转）→ `processed_value`（MAD/角色化中性化/Z-score 后值）。不得直接复用现有 MVP 的 `factor_value` 名称，因为该字段对部分内置因子已经包含取负方向。

### 5.2 标签面板

主键与因子面板一致，包含下一月收益、行业市值残差收益、收益区间起止日期以及无法构造标签的原因。

### 5.3 滚动折定义

每折包含互不重叠的 `train_dates`、`validation_dates`、`test_dates`。折对象不可接收测试期统计量用于 `fit`，所有有状态变换统一提供 `fit(train)` 和 `transform(other)` 接口。

### 5.4 预测表

主键为 `(fold_id, model_id, signal_date, instrument)`，包含原始预测分数、横截面排名、目标分组、模型与配置哈希。

## 6. 数据层设计

### 6.1 框架数据适配器与 RQData 补数适配器

主适配器只读访问 `quant_platform` 的 Parquet 数据湖或平台数据 API，复用 `prices_1d_pre`、`valuation_1d`、`tradability_1d`、`industry_classification` 和 `index_components`。平台 API 使用平台 Token；它与 RQData 凭证是两套独立认证，不得混用。

RQData 补数适配器只在持牌本机运行，职责包括字段发现、缺失数据下载、重试、限频和原始快照，不包含研究逻辑。凭证从 `RQDATAC_KEY` 读取，异常信息必须脱敏；服务器不保存该凭证。

补数按“时间块 × 字段块”下载。每块写入临时原子文件并在校验通过后重命名，避免中断留下看似完整的缓存。清单记录请求范围、行数、校验和、成功状态和 SDK 版本。13,482 个可查询字段只形成目录快照，不等于需要全量物化 13,482 个因子。

### 6.2 存储格式

因子面板优先使用 Parquet，按年份或月份分区；元数据、清单和配置使用 JSON/YAML；小型评价表使用 Parquet 或 CSV。存储层统一处理字段类型、时区和交易日。

### 6.3 数据验证

下载后检查主键唯一性、日期单调性、成分股数量异常、因子覆盖率突变、无穷值、价格非正值和收益极端值。异常分为阻断、可降级和仅告警三级。

## 7. 因子处理设计

### 7.1 训练与应用边界

任何使用统计量或标签的处理器都必须在训练窗拟合。验证期和测试期只能应用训练所得参数。逐月横截面 MAD 与标准化使用当月横截面本身，不使用未来月份；用于选择阈值、因子方向和去冗余代表项的统计量只能来自训练窗。

### 7.2 处理顺序

1. 类型与无穷值清理；
2. 数据质量筛选；
3. 每月横截面 MAD 去极值；
4. 根据 `neutralization_policy` 做中信 `citics_2019` 一级行业和/或对数流通市值中性化；规模因子禁止市值中性化，已中性化因子不重复处理；
5. 每月横截面 Z-score；
6. 训练窗 Rank IC/ICIR 有效性筛选；
7. 训练窗高相关去冗余；
8. 将锁定的因子列表和变换规则应用到验证/测试。

### 7.3 正交化决策

LightGBM、XGBoost 和 CatBoost 能处理相关特征，强制正交化会改变非线性交互并降低解释性。因此正式基线默认使用相关性聚类去冗余。可选对照实验使用训练窗拟合的 PCA/ZCA 变换；该实验必须使用独立实验 ID，不与默认基线混合解释。

## 8. 标签设计

对每个信号日计算下一调仓周期收益，并在当期中证500有效样本中进行横截面回归：

```text
next_return = citics_2019_level1_dummies + log_float_market_cap + residual_return
```

`residual_return` 为模型目标。行业和市值暴露取自信号日可获得数据。标签回归失败时记录原因；不允许使用全样本回归参数。

## 9. 滚动验证设计

### 9.1 默认窗口

- 训练：60个月；
- 验证：12个月；
- 测试：6个月；
- 滚动步长：6个月。

每折流程如下：

1. 锁定三个时间区间；
2. 只用训练窗拟合筛选与处理规则；
3. NNI 使用训练与验证数据调参；
4. 根据验证期 Rank ICIR、Rank IC 选择模型和分组比例；
5. 锁定全部规则；
6. 对测试期执行一次预测；
7. 保存该折产物后进入下一折。

下一折可以使用时间上已经过去的原测试期作为新训练历史，但不得反向修改上一折结果。

### 9.2 时间泄漏防线

- 折生成器断言 `max(train) < min(validation) < min(test)`；
- 处理器记录拟合日期上界，转换时拒绝早于或重叠错误的区间；
- NNI 目标函数不接收测试数据路径；
- 测试预测目录在模型锁定前不可创建；
- 报告展示每折边界和数据量。

## 10. 模型与 NNI 设计

### 10.1 统一模型接口

三个模型实现同一接口：`fit`、`predict`、`get_params`、`feature_importance`、`save`、`load`。统一输入列、样本权重、随机种子、线程预算和早停逻辑。

### 10.2 公平比较

每个模型获得相同最大试验次数或等价计算预算。不得因某模型表现较好临时扩大其搜索空间。模型特有参数分别配置，但公共参数如训练窗口、因子集和评价函数固定。

### 10.3 优化目标

NNI 先最大化验证期 Rank ICIR。在差异小于配置容差时，再比较 Rank IC 均值；仍相同时依次选择较低换手、较短训练时间和较简单模型。测试指标永不进入目标函数。

### 10.4 分组比例

将 `top_bottom_fraction` 作为离散超参数，取值为 `0.10、0.15、0.20、0.25、0.30`。多空比例对称，组内等权。

## 11. 组合与回测设计

### 11.1 理论多空核算

每个调仓日按预测排名构建多头和空头组合。多头权重和为 `+1`，空头权重和为 `-1`，理论组合净敞口为0、总敞口为2。收益分别计算多头、空头贡献后合并。

当股票不可交易时，默认延续旧持仓直到可交易，并记录目标权重与实际权重偏差。新进入但无法买入的股票不建立仓位；无法覆盖空头的情形按理论持有规则处理并单独标注。

### 11.2 成本

成本模型由配置提供，支持佣金、买卖滑点、卖出印花税及可选的固定空头成本敏感性分析。正式报告必须同时显示零成本和成本后结果，并声明未建模真实券源。

### 11.3 RQAlpha 对账

向 `quant_platform` 输出符合其权重包契约的多头目标权重，由平台统一运行 RQAlpha 回测。逐月比较研究回测器与平台结果的持仓、成交、换手、费用和收益。差异超过配置容差时阻止发布正式报告。

## 12. 错误处理与可恢复性

1. API 超时、限频和短暂网络错误采用带抖动的指数退避；认证失败立即终止且不打印密钥。
2. 单个数据块失败时保留成功清单，重跑只请求失败块。
3. 某因子数据不足时记录淘汰原因，不阻断其他因子。
4. 某模型训练失败时记录完整非敏感堆栈；若另外两种模型有效，可按预先定义的降级规则继续，但报告必须醒目标注。
5. 三个模型均失败、标签为空、折区间重叠或发现未来函数时立即终止。
6. 报告生成失败不得覆盖已完成的模型和回测产物。

## 13. 实验产物设计

每次运行生成唯一 `experiment_id`，目录包含：

```text
artifacts/<experiment_id>/
├─ manifest.json
├─ resolved_config.yaml
├─ data_snapshot/
├─ folds/
│  └─ <fold_id>/
│     ├─ selected_factors.parquet
│     ├─ preprocessing.json
│     ├─ nni_trials.parquet
│     ├─ winner_model/
│     ├─ predictions.parquet
│     └─ metrics.json
├─ backtest/
├─ reconciliation/
└─ report/
```

`manifest.json` 汇总配置哈希、依赖版本、数据清单校验和、随机种子、运行状态和异常。任何产物均不得包含 RQData 密钥。

## 14. 测试策略

### 14.1 单元测试

- 月末信号日和下一交易日计算；
- 历史成分股查询；
- MAD、中性化、标准化和退化样本处理；
- Rank IC、ICIR、分组、等权、换手和收益核算；
- 成本计算和不可交易持仓延续；
- 配置校验、哈希与密钥脱敏。

### 14.2 泄漏测试

- 修改测试期标签不应改变训练期因子选择、参数或模型；
- 修改未来因子值不应改变过去预测；
- 测试期股票不得进入训练统计量；
- 当前成分股列表不得回填历史。

### 14.3 集成测试

使用小型、固定的合成数据完成下载适配之外的整条流水线；再使用短期 RQData 样本进行只读烟雾测试。测试不得依赖真实密钥写入仓库。

### 14.4 回归测试

固定数据快照和配置后，对入选因子、模型参数、预测排名、IC 和净值设定容差。依赖升级或数据修订造成变化时必须生成差异报告。

## 15. 实施顺序建议

1. 初始化项目与配置契约；
2. 实现 `quant_platform` 数据湖/API 只读适配和时间点一致性检查；
3. 实现源字段目录、配方目录和正式因子目录；
4. 实现样本、标签和 `60/12/6、步长6个月` 滚动折；
5. 以简单确定性基线贯通因子与回测链路；
6. 接入三模型统一接口；
7. 接入 NNI 和嵌套验证；
8. 接入 `quant_platform` 多头权重包、回测与对账；
9. 完成报告、回归测试和复现说明。

详细实施任务应在用户复核本设计后，使用 Superpowers `writing-plans` 单独生成。

## 16. 已知限制

1. `quant_pool` 已成为 `quant_platform` 的 `feature/research-factor-pool` worktree；研究流水线在该分支实现，保持相邻 `quant_platform/main` 工作区不变。
2. 已完成 RQData 认证与字段枚举，当前快照为 13,482 个可查询字段，其中只有 584 个先验归类为供应商成品因子候选；字段数量不能当作因子数量。
3. RQAlpha 不代表可直接执行理论股票空头，系统只将其用于多头侧验证。
4. 默认阈值和窗口是研究起点，不是经测试期反复优化后的结论。
5. `quant_platform` 现有清洗只有 1%/99% 缩尾和每日 Z-score；MAD、角色化中性化、动态因子目录均属于新实现，不能在接入说明中写成框架已有能力。
