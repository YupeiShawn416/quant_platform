# 中证500基准多因子模型——需求文档

## 1. 文档信息

- 文档状态：V0.3，已同步食材质量、控制变量、PIT事件窗与直通配方要求
- 编制日期：2026-07-14
- 项目类型：A股月频横截面多因子研究基线
- 数据源：`quant_platform` Parquet 数据湖/只读数据 API；持牌本机 RQData 用于字段发现与数据湖补数
- 最终用途：为后续因子研究、模型替换和策略比较提供可复现的统一基准

## 2. 项目目标

构建一套配置驱动、模块化、无未来函数的中证500多因子研究流程。系统先把 RQData 可查询对象拆分为源字段、供应商成品因子和可审计配方，再从正式因子目录构建月度面板，完成数据质量筛选、训练窗内有效性筛选、横截面预处理、去冗余、滚动训练、NNI 调参、三类轻量机器学习模型比较以及理论多空回测。

本项目的成功标准是研究流程严谨、可复现、可扩展，不以获得特定收益率或战胜基准为验收条件。负收益或无显著预测能力也是有效研究结论，禁止为改善结果而使用测试集调参。

## 3. 范围

### 3.1 本期范围

1. 使用历史时点真实的中证500成分股作为动态股票池。
2. 以月度为预测和调仓周期。
3. 完整登记 RQData 权限范围内的可查询源字段；仅将通过定义、时点和数据类型审查的成品/派生因子纳入正式因子目录。
4. 构建下一调仓周期的横截面残差收益标签。
5. 比较 LightGBM、XGBoost、CatBoost 三类模型。
6. 使用 NNI 在滚动训练框架内部优化模型超参数和多空分组比例。
7. 生成 Rank IC、ICIR、理论多空净值、换手率及风险统计。
8. 同时输出毛收益和估算交易成本后的净收益。
9. 提供 RQAlpha 多头侧交易约束验证；理论股票空头由独立研究回测器计算。

### 3.2 本期不包含

1. 实盘下单、模拟盘接入和自动交易。
2. 将理论股票空头描述为可直接成交的融券策略。
3. 真实融券券源、借券费率和融券容量建模。
4. 日内或周频策略。
5. Web 界面、任务调度平台、分布式训练和在线特征库。
6. 深度学习、遗传算法或大规模 AutoML。
7. 对收益率、夏普比率或超额收益作事前保证。

## 4. 已确认的研究口径

| 项目 | 需求 |
|---|---|
| 研究用途 | 可复现的研究基线 |
| 股票池 | 历史动态中证500成分股 |
| 频率 | 月频 |
| 字段范围 | RQData 权限内全部可查询字段，当前快照 13,482 项 |
| 正式因子范围 | 通过非收益资格审查的供应商成品因子与登记配方派生因子 |
| 现有框架 | 复用数据湖、历史成分、可交易性和回测；不覆盖 5 因子日频 MVP |
| 标签 | 下一月横截面残差收益 |
| 验证方式 | 滚动样本外验证 |
| 模型 | LightGBM、XGBoost、CatBoost 公平比较 |
| 调参工具 | NNI |
| 模型主指标 | 验证期 Rank ICIR |
| 模型次指标 | 验证期 Rank IC 均值 |
| 组合形式 | 理论市场中性多空组合 |
| 分组比例 | NNI 从离散候选集中选择 |
| 组内权重 | 多头、空头分别等权 |
| 成本报告 | 毛收益与估算成本后收益均报告 |

## 5. 功能需求

### FR-01 配置与凭证

1. RQData 凭证优先通过系统环境变量 `RQDATAC_KEY` 读取；允许使用被 `.gitignore` 排除的本机 `.env` 作为开发回退，但不得由Agent读取、展示或写入产物。
2. 禁止将密钥写入源码、配置样例、日志、缓存、实验产物或版本控制。
3. 所有研究参数必须来自带版本号的配置文件，包括日期、股票池、滚动窗口、筛选阈值、模型搜索空间、随机种子和成本假设。
4. 每次运行保存脱敏后的最终配置和配置哈希。

### FR-02 数据获取与时点一致性

1. 默认从 `quant_platform` 数据湖或其只读数据 API 取数；服务器不得为本项目直接保存或使用 RQData 凭证。只有持牌本机可执行 RQData 字段发现和补数，再将校验后的 Parquet 同步到数据湖。
2. 使用每个历史调仓时点当时有效的中证500成分股，禁止使用当前成分股回填历史。
3. 因子值、财务数据和行业分类必须按当时实际可获得时间对齐；财务数据按公告或可用日期处理。
4. 月末信号使用调仓日前最后一个可用交易日的数据，收益从下一可交易时点开始计算。
5. 分别保存源字段目录、配方目录、正式因子目录、数据起止日期、覆盖率、源字段和拉取时间快照。
6. 数据更新支持按日期和字段分块、断点续传、缓存复用、限频重试和失败清单。
7. 每次运行记录数据湖快照、代码版本；发生 RQData 直连补数时额外记录 SDK 版本。若供应商修订历史数据，应能识别结果变化。
8. 财务源字段必须在历史动态中证500范围完成非收益元数据体检，记录最早可用日期、覆盖率、有效年份、适用行业和质量快照；行业专属字段按适用行业评价。
9. 供应商财务因子的PIT检查必须使用固定、可复现的财报公告事件窗口；抽样通过只能记为 `sample_alignment_passed`，不能单独证明 `verified`。

### FR-03 样本与标签

1. 默认剔除调仓日不可交易、停牌、ST/退市整理、上市不足 120 个交易日及缺少下一期收益的股票；具体规则可配置。
2. 标签为下一调仓周期个股收益的横截面残差。
3. V1 标签残差化解释变量使用现有数据湖的中信 `citics_2019` 一级行业哑变量和对数流通市值；行业版本必须固定并记录。只有在新增并验证申万 PIT 数据后，才允许通过新版本配置切换申万口径。
4. 标签构造只允许使用调仓时点已知暴露及随后真实发生的收益，不得跨测试期估计全样本参数。
5. 行业、市值、ST、停牌、涨跌停、上市状态和上市天数来自独立控制变量目录；控制变量不作为预测因子，也不参与IC或去冗余。

### FR-04 因子质量筛选

1. 第一阶段仅按数据质量筛选，不使用收益信息。
2. 默认要求因子在训练窗内至少有 24 个月有效观察；月度横截面覆盖率中位数不低于 80%，有效月份占比不低于 80%。
3. 删除全常量、近常量、明显无穷值、无法解释的数据类型及元数据不完整因子。
4. 阈值必须可配置，并在每个滚动折中记录入选、淘汰原因。
5. 配方食材质量筛选与成品因子训练窗质量筛选是两个门禁：前者不读取收益并决定字段是否推荐用于配方，后者在每个滚动折内决定正式因子是否参与建模。
6. 食材状态至少区分 `preferred`、`specialized`、`sparse`、`insufficient_history` 和 `pending_review`；低质量字段仍保留在完整源目录。

### FR-05 因子有效性筛选

1. 第二阶段只在当前滚动训练窗内使用收益标签进行筛选。
2. 默认宽松门槛为训练窗 `|Rank IC 均值| >= 0.01` 或 `|Rank ICIR| >= 0.20`，且至少满足 55% 的方向一致月份；阈值可配置。
3. 因子方向由训练窗决定，验证期和测试期不得反向修正。
4. 验证期与测试期严禁参与因子筛选、阈值选择或淘汰规则修改。

### FR-06 横截面预处理

1. 每个调仓日独立进行横截面处理。
2. 默认顺序为：无穷值转缺失、MAD 去极值、按因子角色中性化、Z-score 标准化。
3. MAD 默认边界为中位数加减 `3 × 1.4826 × MAD`。
4. 中性化暴露使用中信 `citics_2019` 一级行业哑变量和对数流通市值。估值、盈利、成长、质量、现金流和普通选股 Alpha 默认行业+市值中性化；规模因子不得做市值中性化；已中性化因子不得无依据重复处理。
5. 每个正式因子必须在元数据中固定 `neutralization_policy`、原因和版本。
6. 横截面样本不足、方差为零或回归矩阵退化时必须记录并按明确的降级规则处理，不能静默跳过。
7. 缺失值不得使用验证期或测试期统计量填补；树模型可保留的缺失值优先保留。
8. 中性化和可交易性过滤只能读取已通过定义、PIT和覆盖率检查的 `control_field_catalog`；控制变量不得混入模型特征矩阵。

### FR-07 去冗余与正交化

1. 默认采用训练窗内的高相关因子去冗余，而不是对树模型强制全量正交化。
2. 默认按 Spearman 相关系数绝对值 `>= 0.90` 聚类或成组，每组保留覆盖率和训练窗稳定性更高的代表因子。
3. 完整正交化作为可配置对照实验；若启用，变换矩阵只能在训练窗拟合，再原样应用到验证期和测试期。
4. 禁止使用依赖因子输入顺序且未记录顺序的 Gram-Schmidt 结果作为正式基线。

### FR-08 滚动训练与验证

1. 默认每折使用 60 个月训练、12 个月验证、6 个月测试，并按 6 个月步长向前滚动。
2. 数据不足时不缩短为不具可比性的窗口；应从满足最小历史长度的首个折开始。
3. 每个测试折开始前，重新完成质量筛选、有效性筛选、预处理参数拟合、去冗余、模型调参与模型选择。
4. 测试期只允许生成一次预测和评价，不允许反馈到当前折的任何选择步骤。
5. 所有随机过程使用固定且记录的随机种子。

### FR-09 NNI 调参与模型选择

1. LightGBM、XGBoost、CatBoost 使用同一训练样本、验证样本、因子输入和资源预算。
2. NNI 只访问训练期与验证期，测试期对调参器不可见。
3. 主排序指标为验证期 Rank ICIR；Rank ICIR 相同或在预设容差内时，以 Rank IC 均值择优。
4. 同时记录 Rank IC 标准差、正 IC 月份占比、最大连续失效月份和训练耗时。
5. 多空两端比例从 `10%、15%、20%、25%、30%` 中选择，两端比例相同。
6. 搜索空间、最大试验次数、单次超时、并发数和早停条件必须固定并记录。
7. 三个模型比较完成后，每个滚动折只选择一个胜出模型用于该折测试期预测。

### FR-10 理论多空研究回测

1. 每月按模型预测分数排序，做多最高分组、做空最低分组，两端分别等权并保持名义资金相等。
2. 组合净敞口默认约为零；报告实际多头、空头、净敞口和总敞口。
3. 主要报告毛收益；净收益按配置的佣金、滑点、印花税和换手成本估算。
4. 明确标注净收益未包含真实券源约束和借券成本，不得解释为可直接实盘的融券收益。
5. 对停牌、涨跌停、退市、缺失价格和无法调仓情形采用显式规则，并输出受影响记录。

### FR-11 RQAlpha 验证边界

1. RQAlpha 用于验证多头侧的交易日历、成交约束、费用配置和净值计算一致性。
2. 理论股票空头净值由独立研究回测器生成，不伪装为 RQAlpha 可成交股票空头订单。
3. 两套回测对相同多头信号的持仓、换手和收益必须进行逐期对账，并解释超出容差的差异。

### FR-12 结果与报告

每次正式实验至少输出：

1. 脱敏配置、配置哈希、代码版本、依赖版本、随机种子和运行时间。
2. 因子元数据快照、质量报告、各折筛选结果及淘汰原因。
3. 月度 Rank IC 序列、均值、标准差、ICIR、正 IC 比例和连续失效区间。
4. 三类模型的验证结果、最优参数、训练耗时和每折胜出模型。
5. 理论多空的毛净值、成本后净值、月度收益、回撤、波动率、Sharpe、换手率和暴露。
6. 多头、空头及多空组合的分解结果。
7. 测试期合并结果和逐折结果，禁止只展示表现最好的折。
8. 异常、失败重试、数据缺口和降级处理清单。

## 6. 非功能需求

### NFR-01 可复现性

在数据快照、代码版本、配置和环境一致时，重复运行得到相同入选因子、超参数、预测和净值；浮点差异应在预先定义的容差内。

### NFR-02 模块化

数据、样本、筛选、预处理、去冗余、训练、调参、组合、回测和报告模块通过明确的数据契约连接，可独立测试和替换。

### NFR-03 可审计性

任何股票、月份、因子或模型被剔除、降级或选择时，均能查询原因。日志不得包含密钥和完整敏感凭证。

财务字段体检必须记录股票池快照和适用行业；PIT抽样必须记录证券、公告事件、观察日期、字段、期望变化边界、实际结果和规则版本；供应商候选的每次状态迁移必须可追溯。

### NFR-04 性能与恢复

大规模因子数据必须使用列式存储和缓存，避免重复请求；网络或配额错误可从最近成功分块恢复，而不是重跑全部历史。

### NFR-05 安全

凭证不得进入Git、代码、日志、缓存、manifest或报告；示例配置只包含环境变量名。本机 `.env` 必须被忽略且只能由运行时加载。用户此前在对话中暴露的密钥视为失效凭证，不得使用。

## 7. 验收标准

1. 能从空缓存开始完成至少一个完整滚动折，并从缓存复跑得到一致结果。
2. 自动化检查证明指数成分、因子、行业、市值和预处理参数不存在测试期泄漏。
3. 三个模型在相同数据、预算和指标下完成比较，NNI 试验记录可追溯。
4. 每个测试折只在模型锁定后生成一次样本外结果。
5. 理论多空回测与 RQAlpha 多头验证边界在报告中明确，不误导为可交易股票空头。
6. 所有规定产物完整生成；因子缺失、接口限频或单模型失败时有明确错误或降级报告。
7. 测试覆盖关键时间对齐、滚动切分、横截面处理、筛选隔离、组合权重和收益核算逻辑。
8. 不以正收益作为通过条件；若模型无效，系统仍须准确报告无效结论。
9. 13,482 个可查询对象全部进入源字段目录，但原始报表字段不会未经配方直接入模。
10. 现有 5 因子 MVP 的日频 `factor_value/factor_score` 语义和文件不被覆盖。
11. 9,858个财务字段均保留在源目录并获得食材质量状态，行业专属字段不会因全市场覆盖率低被误杀。
12. 行业、市值和可交易性条件进入独立控制变量目录，且不会出现在因子IC、去冗余或模型特征清单中。
13. 584个供应商候选均有定义和PIT状态；任何事件窗提前变化都会阻断，抽样通过不会自动成为 `verified` 或 `eligible`。
14. 通过门禁的供应商因子使用 `identity` 直通配方，与自研配方共用下游接口；生成配方本身不授予建模资格。

## 8. 风险与约束

1. RQData 账户权限、历史深度和因子元数据可能限制实际可用因子范围。
2. 因子库可能存在版本修订，若无法获得不可变数据快照，跨时间完全复现存在供应商侧限制。
3. 因子数量相对月度样本较大，三模型和 NNI 的组合存在明显过拟合风险，必须限制搜索预算并坚持嵌套验证。
4. 树模型并不需要传统线性正交化；强制正交化可能损失非线性交互，因此默认只做去冗余。
5. 理论股票空头忽略券源和借券成本，其净值只能衡量研究信号，不代表实际收益。
6. `quant_pool` 已作为 `quant_platform` 的 `quant_pool` 分支worktree；开发不得直接发生在相邻 `quant_platform/main` 工作区。
7. 现有框架只实现 5 个静态日频因子及 1%/99% 缩尾、Z-score；MAD、角色化中性化、动态目录和滚动筛选均是本项目待实现能力。

## 9. 后续待复核项

以下均已有默认值，可在实施计划前调整：因子覆盖率阈值、有效性门槛、上市天数、相关性阈值、NNI 预算、成本参数及测试起止时间。窗口固定为 `60/12/6、步长6个月`；V1 行业口径固定为 `citics_2019` 一级，切换行业体系必须新建数据与配置版本。
