# 现有因子库框架分析说明

## 1. 结论

`quant_platform` 可以直接复用数据湖、历史中证500成分、可交易性、因子日值存储、单因子诊断、权重包和回测链路，但它目前只是一个 **5 因子的日频 MVP**，不是待建的月频基准多因子模型。

因子池工程应先在 `quant_pool` 中建设独立的字段目录、因子配方目录、正式因子目录和月度面板，通过现有数据湖/API 取数；模型稳定后再把模型权重交给 `quant_platform` 回测。首期不应把 13,482 个 RQData 字段写进现有静态注册表，也不应覆盖现有 5 因子的存储语义。

- 核对日期：2026-07-16
- 页面：http://39.106.218.30/ui/factors
- 代码基准：`../quant_platform`
- 事实来源：框架 README、规格文档、`src/rq_platform/factors/` 实现与对应测试

## 2. 当前框架事实

### 2.1 数据层

框架以 Parquet 数据湖为长期存储，DuckDB/数据 API 用于查询。默认数据根目录为 `data/research_data/rqdata`，当前定义的主要数据集为：

| 数据集 | 用途 |
|---|---|
| `trading_calendar` | 交易日历 |
| `instruments` | 证券及上市信息 |
| `prices_1d_pre`、`prices_1d_none` | 前复权/不复权日行情 |
| `index_prices_1d` | 指数行情 |
| `tradability_1d` | 停牌、涨跌停等可交易状态 |
| `valuation_1d` | 市值、估值、换手率 |
| `industry_classification` | 历史行业分类 |
| `index_components`、`index_weights` | 历史指数成分与权重 |

`index_components` 已覆盖中证300、500、1000，因子计算器也支持 `csi300`、`csi500`、`csi800`。因此“现有框架只能使用全市场”不准确：5 个定义的默认股票池是 `all`，但计算器具备按历史中证500成分计算的能力。

当前行业数据 V0 口径是 **中信行业 `citics_2019` 一级**。申万一级并非现有数据契约的一部分；若模型必须使用申万，应先新增、验证并冻结申万 PIT 行业数据，不能在文档中把它写成已存在能力。

框架设计要求服务器通常不直接连接 RQData。持牌本机负责更新 Parquet 后再同步到服务器。因子发现或补数也应遵守这一边界。

### 2.2 因子库 MVP

`FactorRegistry` 当前由静态 `BUILTIN_FACTORS` 驱动，只有以下 5 个内置因子：

| ID | 计算值 | 数据集 |
|---|---|---|
| `market_cap` | `-log(market_cap)` | `valuation_1d` |
| `momentum_20d` | `close / close.shift(20) - 1` | `prices_1d_pre` |
| `reversal_5d` | `-(close / close.shift(5) - 1)` | `prices_1d_pre` |
| `turnover_rate` | `-turnover_rate` | `valuation_1d` |
| `volatility_20d` | `-rolling_std(ret_1d, 20)` | `prices_1d_pre` |

`FactorCalculator` 输出日频 `factor_value`，再统一执行每日横截面的 1%/99% 分位数缩尾与 Z-score，结果写入 `factor_score`。`FactorStore` 按因子、年份保存 Parquet，最低字段契约只有：

```text
trade_date, order_book_id, factor_value, factor_score
```

当前实现没有 MAD 去极值、行业/市值中性化、因子配方版本、字段目录、动态注册、缺失原因或滚动折筛选。概念规格中虽然出现了 `factor_version` 等字段，但存储实现尚未强制这些字段；设计时必须区分“规格设想”和“代码已实现”。

### 2.3 分析与输出

`FactorAnalyzer` 基于日行情计算覆盖率、日度 IC、分组收益/净值、头部分组换手和最新高低分股票，并把结果保存为 JSON、Markdown 和 CSV。默认最低可用覆盖率为 50%。这些产物适合旧 MVP 单因子诊断，不能直接充当月频残差收益标签下的滚动样本外筛选结果。

框架现有权重接口生成多头、无杠杆、无股票空头的权重。目标模型的理论多空研究仍需独立核算；实际回测接入时优先输出多头权重包给框架。

## 3. 已确认的缺口

| 目标能力 | 当前框架 | 处理方式 |
|---|---|---|
| 13,482 个源字段清单 | 无 | 在 `quant_pool` 新建 `source_field_catalog` |
| 财务字段食材质量体检 | 无 | 在动态历史中证500上建立 `ingredient_health_catalog` |
| 行业、市值和可交易性控制目录 | 数据分散在多个数据集 | 新建独立 `control_field_catalog`，禁止混入预测因子 |
| 字段到因子的可审计配方 | 无 | 新建 `factor_recipe_catalog` |
| 供应商因子统一接入 | 直接读取或静态公式 | 通过受门禁的 `identity` 直通配方统一包装 |
| 财务因子PIT事件窗 | 无 | 使用固定公告事件和前后交易日做反证性抽样 |
| 可扩展正式因子目录 | 静态 5 因子 | 新建独立 `factor_catalog`，稳定后再设计平台扩展 |
| 月末中证500面板 | 日频逐因子长表 | 从数据湖生成独立月度面板 |
| MAD 与角色化中性化 | 1%/99% 缩尾 + Z-score | 新流水线实现，保留旧 MVP 语义 |
| 滚动样本外筛选 | 全区间单因子诊断 | 使用 60/12/6、步长6个月的折内筛选 |
| 月度残差收益标签 | 日度远期收益 | 新建标签模块 |
| 三模型与 NNI | 无 | 在 `quant_pool` 实现 |
| 理论多空 | 仅多头权重 | 独立研究核算；多头交由平台验证 |

## 4. 必须修复的语义风险

1. 现有 `market_cap`、`turnover_rate`、`volatility_20d` 等公式已经取负，同时元数据又写 `lower_is_better`，存在重复反向风险。新因子目录必须保存未经“越高越好”翻转的配方结果，并把方向作为训练窗属性；旧 MVP 不直接改写，接入时做显式映射。
2. 市值计算器会在多个候选市值列中选择覆盖率最高者。若不记录实际 `source_field`，不同快照可能选到不同来源。新面板必须固化源字段和版本，不允许运行时静默换源。
3. `factor_value` 在现有 MVP 中不是严格的供应商原值，而是已经过公式和取负的计算值。新数据契约应使用 `source_value → recipe_value → processed_value/model_value` 分层，避免复用同名字段造成误解。
4. 页面/API 的 401 是平台 API Token 鉴权失败，不代表 RQData 认证失败。代码仓库已经给出合法的数据 API 和本地数据湖访问方式，无需把“直接访问生产数据库”作为默认方案。
5. 最新数据日、最近达到覆盖率门槛的可用日和标签成熟日必须分开保存，不能用一个 `latest_date` 代替。

## 5. 推荐接入架构

```text
持牌本机 RQData 枚举/补数
          │
          ▼
quant_platform Parquet 数据湖 / 只读数据 API
          │
          ▼
quant_pool
字段目录 ─┬→ 食材质量目录 → 自研配方 ───────────┐
          ├→ 供应商定义/PIT审计 → identity配方 ├→ 正式因子目录
          └→ 控制变量目录 ─────────────────────┘        │
                                                       ▼
                                               月度中证500面板
                                                       │
                                                       ▼
          滚动筛选 → 三模型/NNI → 月度预测与权重
                              │
                ┌─────────────┴─────────────┐
                ▼                           ▼
        独立理论多空核算          quant_platform 多头权重包/回测
```

这个边界既复用框架已有能力，也避免在研究口径尚未稳定时破坏静态 5 因子 MVP。

## 6. 文档口径

从本次修订起，所有文档统一使用以下术语：

- **源字段**：RQData 可查询字段，13,482 是该层数量；
- **配方食材**：通过非收益元数据体检、可供研究员优先引用的源字段；低质量字段仍保留在源目录；
- **控制变量**：行业、市值、ST、停牌、涨跌停等基础设施对象，不是选股因子；
- **成品因子**：供应商已有明确公式的 584 个候选对象，仍需资格审查；
- **派生因子**：由登记配方从源字段计算的研究变量；
- **正式因子**：通过非收益资格审查后进入 `factor_catalog` 的成品或派生因子；
- **折内入模因子**：仅在某个训练折通过质量、有效性和去冗余筛选的正式因子。

以上七层不得再混称“全部基础因子”。

PIT事件窗口抽样只能发现明确穿越，不能仅凭抽样通过宣称供应商全历史 `verified`。供应商因子即使使用 `identity` 配方统一包装，也必须先通过定义和PIT状态门禁。
